# Changing the accession of plots: what should change with it?

Draft issue for solgenomics/sgn, written while reviewing #6384 (and #6353, #4642).

## Summary

The code paths that change the accession of plots in a trial behave differently. Two of them now also rewrite replicate numbers and plot names. Rewriting replicates was never requested or discussed: it came in with #5985 (the fix for the CSV header parsing in #5979). It is wrong for every blocked design, and with #6384 it would also apply to Field Layout Tools → Replace Accession.

I propose to agree on what an accession change means before more code goes into it. After that, all entry points can use one implementation.

## What a plot is

A plot is a place in the field. Its plot number, block, replicate, row and column describe that place, and the design (and the analysis) depends on them. The accession is what grows there. When a breeder changes the accession of a plot, they are correcting what was planted (#2097: "a shortage of planting material"), or editing a design that has not been planted yet. In both cases the place stays the same.

In RCBD, RRC and URDD the design stores `rep_number = block_number`. In Alpha and Lattice the rep is the replication that contains the incomplete blocks, and in split plot it is the block. Only in CRD is the rep just "the n-th plot of this accession". The analyses use it as a factor: `R/heritability/h2_rscript.R` fits `lmer(trait ~ (1|germplasmName) + replicate)`, and `R/solGS/anova.r` and `R/stability/ammi_script.R` use `replicate` too.

## What happens now

RCBD with 3 reps (blocks 1–5, 6–10, 11–15), `replace_stock` test_accession3 → test_accession1 with #6384 (`t/unit_mech/review_rcbd.t`):

```
plot  4 block 1 rep 2 test_accession1  test_trial-rep1-test_accession1_4  <-- rep != block, name says rep1
plot  5 block 1 rep 3 test_accession1  test_trial-rep1-test_accession1_5  <-- rep != block (plot was not changed)
plot  8 block 2 rep 4 test_accession1  test_trial-rep2-test_accession1_3  <-- rep 4 in a 3-rep trial
plot 10 block 2 rep 5 test_accession1  test_trial-rep2-test_accession1_5
plot 11 block 3 rep 6 test_accession1  test_trial-rep3-test_accession1_1
```

Since #5985 (April 2026) the same happens with the upload Change Accessions and with single plot replace. `audit_reps.sql` lists every replicate rewritten since then, with the value before, so affected trials can be found and repaired.

The entry points today:

| Entry point | plot_of + children | Replicates | Plot names | Layout cache | Transaction |
|---|---|---|---|---|---|
| Replace Accession (`replace_stock`), master | SQL | no | no | **not regenerated** (#4642) | no |
| same, with #6384 | SQL | rebuilt | substring / template | regenerated after | yes |
| Single plot (`replace_plot_accessions`) | ORM | rebuilt | substring / template / given | regenerated | **no**: an error from the rename leaves the accession changed |
| Upload Change Accessions | ORM | rebuilt | substring / template / file | regenerated | yes |
| Substitute (swap two plots) | SQL over all relationships | no | no | regenerated | no |
| BrAPI v2 PUT observationunits | `replace_plot_accession_fieldMap` called with 3 of its 4 arguments since 1423e6b4 | no | no | no | no |

The rename and replicate code is copied three times in `SGN::Controller::AJAX::TrialMetadata`.

The plot name tracks the accession only partly. The default names (no template) are `TRIAL-rep{rep}-{ACCESSION}_{n}`. The substring rename changes the accession part but not the rep part. Templates such as `[trialName, accessionName, repNumber]` (accepted as unique by `AddAutogeneratedNameMetadata`) cannot stay unique when two accessions are merged unless reps are renumbered. That seems to be the reason for the renumbering: the naming scheme decides the design data, when it should be the other way round.

Plot names are also identifiers outside the database: printed labels and barcodes, Field Book files that were exported but not yet uploaded, BrAPI `observationUnitName`, and tissue sample names that are derived from them. `update_fieldmap_precheck` only knows about uploaded phenotypes and seedlots.

## Proposal

1. **An accession change changes the accession, not the place.** It updates `plot_of` and the `plant_of` / `subplot_of` / `tissue_sample_of` links of the children. It does not touch plot number, block, replicate, row or column. (If CRD trials need renumbering, that can be a separate, explicit action.)
2. **Renaming is an explicit, previewed choice.** The dialog shows old name → new name for every plot that would change (whole name parts only, or the trial's template), and any conflicts, before anything is written. "Keep names" is always possible. The upload keeps its `new_plot_name` column. Renames run in two passes, so names can move between plots.
3. **One implementation**, for example `CXGN::Trial::AccessionChange`, with `plan(\@changes, \%options)` that returns the preview and `apply($plan)` that does everything in one transaction and invalidates the layout cache. Replace Accession, single plot, upload, substitute and BrAPI build the list of `{plot_id, new_accession_id}` and call it. Tests live in `t/unit_fixture` against this one class.
4. **The layout cache is never the source for a change**: read the plots from the database, or regenerate first. After the change, invalidate it, and refresh the matviews after commit.
5. **Repair**: run `audit_reps.sql` on the production databases and restore `replicate_before` for blocked designs.

## For #6384

Keep what fixes #4642: the atomic swap, regenerating the layout cache (before reading it as well), the matview refresh, and the test for the Experiment Usage pages. Leave out `rebuild_trial_plot_replicates` until 1 is decided. For renaming, keep the whole-part match from #6353 (it reports names it cannot change safely) rather than the plain substring replacement.

Questions:
- Is there a use case where the replicate *should* change when an accession is replaced? Which designs?
- Should renaming be on by default when the plot name contains the old accession as a whole part?
- Should the precheck also warn when labels may already be printed or Field Book files exported (for example a trial with a planting date, or with tissue samples)?
